Workflow

Each tool reads the output of the one before it. The flood raster is an input of the first tool, so no label field is needed on your points or grid.

01Build the table

Flood raster and predictor rasters, read at your points or grid cells, written to a CSV.

02Check the table

Class balance, leakage hints, correlation and a suggested block size.

03Train and validate

Nested spatial cross-validation, confidence intervals, SHAP, residual maps.

04Map

Susceptibility raster, classes, styles and an extrapolation warning raster.

05Independent test

Scores on data the models never saw, with an overlap check.

06Self-test

Runs the whole chain on synthetic data and says whether it works.

Susceptibility map

Five classes from the ensemble prediction. With quantile classes each class holds about the same number of cells by design, so the map ranks places against each other. It is not a probability of flooding.

Reading these results

This page shows one run of the plugin on 3,908 grid cells of 100 m around 24.40° N, 91.05° E. The flood label comes from a flood record raster, and the predictors are distance to river, distance to road, elevation, slope and NDVI.

The numbers are a demonstration of what the reports look like, not a finished flood study. Two limits of this run are worth knowing. Permanent water was not excluded from the training table, so the river channel is scored as a non-flood area. And the independent test used the training table, which the plugin flags as not valid. Rebuild the table with the water-exclusion option of tool 01 before you use a map for decisions.

Always true of susceptibility maps
  • A predictor must be known before the flood. A layer made from the flood image leaks the answer.
  • Scores are susceptibility ranks, not flood depth, return period or risk.
  • Tree models do not enforce the direction you give a predictor; the direction only changes scaling.
  • Check the extrapolation raster before trusting cells outside the training range.
